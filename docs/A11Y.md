# AuraWin — Accessibility

## Color-blind correctness (Phase 1, required — not optional)
AuraWin is a *color*-prediction game and ~8% of males have red-green color-vision deficiency.
Color alone must never be the only signal.

- **ResultBall** — show the number (already present) **and** a small color glyph/letter
  (R / G / V) or shape so red vs green is distinguishable without hue.
- **Color bet buttons** — label each ("Green", "Red", "Violet") + an icon/shape, not just a
  swatch.
- **Records / trend cells** — pair color with a letter or pattern.
- A `Settings.colorBlindCue` toggle forces cues fully on; default derives sensibly.

## Motion
Respect `prefers-reduced-motion` (handled globally in `globals.css`): confetti, pulse, count-up,
sheet/toast transitions reduce to near-instant. The celebration must remain comprehensible
without animation.

## Keyboard & focus
- All interactive elements reachable and operable by keyboard.
- Visible focus rings (do not remove outline without an equivalent).
- AuthModal / Sheet / AgeGate trap focus and close on Esc; restore focus on close.

## Semantics
- Buttons are `<button>`, links are `<a>`; icon-only controls get `aria-label`.
- Countdown announces politely (aria-live) at meaningful thresholds, not every 250ms.
- Sufficient text contrast across all 3 themes (verify per theme in pixel-QA / theme-audit).

## Verification
Color-blind cue present on every color element; reduced-motion honored; keyboard-only run of the
core bet flow; contrast spot-check per theme.
